# VillagerPoiHalt v1.1.0 — POI Spawner Stripping

**Release date:** 2025 · **Type:** minor (major fix / new feature) · **Jar:** `VillagerPoiHalt-1.1.0.jar`

v1.0.0 stopped **villager brains** from triggering the Folia#292 sync POI
load — but a production watchdog report showed a **135-second region stall**
from a completely different trigger of the same engine bug:

```
CatSpawner.spawnInVillage
  → PoiManager.getCountInRange
    → PoiManager.getOrLoad            ← same unsafe sync POI load
      → ChunkHolderManager.loadPoiChunk   ← region thread parked 135s
```

`CatSpawner` is a **world-level** custom spawner ticked from
`ServerLevel.tickCustomSpawners()` — it runs regardless of villager AI, and
so do two others that also scan the POI index. v1.1.0 removes them.

## 🔧 Changes

- **Added: POI spawner stripping** — reflectively removes the three vanilla
  world spawners that perform POI scans on region tick threads:
  - `CatSpawner` — scans 48 blocks around a random player for bed POIs every
    60s before spawning village cats *(the 135s stall above)*
  - `VillageSiege` — checks POI counts ("is this a village?") before zombie
    sieges
  - `WanderingTraderSpawner` — searches for a bell (MEETING) POI within 48
    blocks when picking a trader spawn point
- **Added: config section** `strip-poi-spawners` with per-spawner toggles
  (all default **on**)
- **Added:** stripping is re-applied on `WorldLoadEvent` for late-loaded
  worlds, and is fully reversible at runtime — set an option to `false` and
  run `/vpoihalt reload`; the cached spawner instance is restored, no restart
  needed
- **Changed:** `/vpoihalt status` now shows spawner-strip state per world
- **Docs:** explained why spawn-event cancellation can't fix this (the POI
  scan happens *before* any spawn attempt)

## ⚠️ Side effects while stripped

| Spawner | Effect |
| --- | --- |
| `cat-spawner` | No naturally-spawning village/witch-hut cats (breeding & spawn eggs still work) |
| `village-siege` | No zombie sieges |
| `wandering-trader` | No wandering trader (alternative: `/gamerule doTraderSpawning false`) |

## 🧵 Technical notes

- The spawner list swap is a single reference assignment done on the global
  region thread (enable / world load / reload); region threads reading a
  briefly-stale reference is harmless.
- `ServerLevel.customSpawners` is located by its Mojang-mapped name with a
  defensive heuristic fallback (any `List` field whose elements implement
  `CustomSpawner`) in case of future renames.
- **JDK 26+ note:** the field is `final`; if a future JDK blocks final-field
  mutation, add `--enable-final-field-mutation=ALL-UNNAMED` to the server
  JVM flags. Works out of the box on JDK 17–25.

## ⬆️ Upgrade notes

Drop-in replacement. On first start the new `strip-poi-spawners` section is
absent from your existing `config.yml` — the plugin then uses the defaults
(all stripping **enabled**). Add the section from the bundled config if you
want to turn any of it off:

```yaml
strip-poi-spawners:
  enabled: true
  cat-spawner: true
  village-siege: true
  wandering-trader: true
```
