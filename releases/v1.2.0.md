# VillagerPoiHalt v1.2.0 — Managed Employment & Restock

**Release date:** 2025 · **Type:** minor (major feature) · **Jar:** `VillagerPoiHalt-1.2.0.jar`

Disabling villager AI (v1.0.0) fixed the Folia#292 stalls, but it also took
away two things villagers normally do through the **brain** — the exact code
path we ban:

- **Taking a job** — vanilla assigns a profession via the `AcquirePoi`
  behavior (a POI lookup). With AI off, villagers stay unemployed forever.
- **Restocking trades** — also brain/work-schedule driven, so trades stayed
  sold out.

v1.2.0 reimplements both **without ever touching `PoiManager`**, so you keep
the crash fix *and* get working, restocking trade villagers.

## 🔧 Changes

- **Added: Managed employment** — the plugin runs its own job-site scan around
  each managed (halted), unemployed **adult** villager and assigns the matching
  profession, then generates its trades directly:
  - Reads **only blocks in already-loaded chunks**, on the villager's **own
    region thread**, guarded by `isChunkLoaded` + try/catch — so it can never
    force a chunk/POI load or cross a region boundary.
  - Trades are populated by calling vanilla `Villager.updateTrades()`
    reflectively (the same routine used on level-up) — no brain tick, no POI.
  - Nitwits and already-employed villagers are left untouched.
  - Full vanilla job-site → profession mapping (composter→farmer,
    lectern→librarian, blast furnace→armorer, … 13 total).
- **Added: Managed restock** — resets each trade's use counter on a fixed
  schedule so sold-out trades come back. Pure Bukkit API (`setUses(0)`), no
  reflection. Default cadence: **4 times per 20 minutes** (every 5 minutes),
  exactly as requested.
- **Added: config sections** `managed-employment` and `managed-restock`.
- **Changed:** `/vpoihalt status` now reports employment radius/interval and
  restock cadence.
- **Changed:** both schedulers restart on `/vpoihalt reload` and stop cleanly
  on plugin disable.

## ⚙️ New config

```yaml
managed-employment:
  enabled: true
  search-radius: 4          # blocks to scan around each villager (1-8)
  check-interval-seconds: 10

managed-restock:
  enabled: true
  times-per-cycle: 4        # 4 restocks...
  cycle-minutes: 20         # ...per 20 minutes  => every 5 min
```

## 🧵 Folia threading

Two repeating tasks run on the `GlobalRegionScheduler`. Each cycle they take a
concurrent snapshot of every world's villagers, then hop to each villager's
`EntityScheduler` so every block read and entity mutation happens on the
region thread that owns it. State is re-checked after the hop (the snapshot can
go stale). No legacy Bukkit scheduler is used anywhere.

## ⚠️ Notes & limitations

- Only villagers **this plugin manages** (halted) are employed/restocked. In
  global mode that's all of them; in scoped mode it's those inside your areas.
- Employment requires the **job-site block to be within `search-radius` and in
  a loaded chunk** at scan time — put job blocks right next to your villagers
  (as in a normal trading hall) and they'll get hired within one interval.
- The job block is not "claimed" as a POI (that's the whole point), so two
  villagers next to the same block could both take that profession. Give each
  villager its own job block if you need distinct professions.
- Trade generation uses reflective `Villager.updateTrades()` (Mojang-mapped,
  matches Paper/Folia 1.20.5+). If a future mapping change hides it, the plugin
  logs a warning and still assigns professions (trades then appear on the
  villager's first natural refresh / can be seeded another way).

## ⬆️ Upgrade notes

Drop-in replacement. The new `managed-employment` / `managed-restock` sections
are absent from an existing `config.yml`, so the built-in defaults apply
(both **on**). Copy the sections from the bundled config to tune or disable.
