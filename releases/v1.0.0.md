# VillagerPoiHalt v1.0.0 — Initial Release

**Release date:** 2025 · **Type:** Initial release · **Jar:** `VillagerPoiHalt-1.0.0.jar`

**Stop villagers from freezing your Folia region threads.**

VillagerPoiHalt is a targeted workaround for the confirmed, unresolved Folia
engine bug [PaperMC/Folia#292](https://github.com/PaperMC/Folia/issues/292),
where villager brain behaviors (`AcquirePoi`, `YieldJobSite`,
`PoiCompetitorScan`) trigger **synchronous POI chunk loads** via
`PoiManager.getOrLoad()` — blocking the region tick thread and causing
watchdog stalls. There is no server config that prevents this; it has to be
stopped at the plugin level. That's what this does.

## ✨ Features

- 🛑 **Halts villager brain ticking** via `setAI(false)` — the POI-scanning
  behaviors never run, so the sync load never happens
- 💰 **Trading still works** — the right-click trade GUI doesn't depend on AI
  ticking (halted villagers won't move, work, restock, or breed)
- 🌍 **Flexible scoping** — halt every villager globally, or only inside
  defined areas:
  - `radius:<world>:<x>:<z>:<radius>` — world + radius zones (e.g. your trading hall)
  - `wg:<world>:<region>` — WorldGuard regions (optional soft dependency)
- 🔁 **Full coverage** — applies on fresh spawns, on chunk load for existing
  villagers, and via a startup sweep on plugin enable
- 💾 **Restart-safe & reversible** — halted villagers are tagged with a
  persistent data marker, so the plugin only ever restores villagers *it*
  halted (map-maker/other-plugin NoAI villagers are never touched)
- 🧵 **100% Folia-thread-safe** — every entity mutation runs on the owning
  region thread via `entity.getScheduler()`; no legacy Bukkit scheduler,
  no `TickThread` errors

## 🕹️ Commands (`vpoihalt.admin`)

| Command | What it does |
| --- | --- |
| `/vpoihalt status` | Count of villagers currently halted by this plugin + active mode |
| `/vpoihalt toggle <world> <x> <z> <radius>` | Halt/unhalt villagers in a radius at runtime — no restart needed |
| `/vpoihalt restore <world> <x> <z> <radius>` | Cleanly re-enable AI (e.g. keep one working villager for testing) |
| `/vpoihalt reload` | Reload config.yml |

## 📋 Requirements

- **Server:** Folia 1.21.x (also runs on Paper) — `folia-supported: true`
- **Java:** 21+
- **Optional:** WorldGuard 7.x for `wg:` region scoping

## 📦 Installation

1. Drop `VillagerPoiHalt-1.0.0.jar` into `plugins/`
2. Restart the server
3. (Optional) Edit `plugins/VillagerPoiHalt/config.yml` to scope halting to
   specific areas, then `/vpoihalt reload`

Default config halts **all** villagers globally. Set
`disable-ai-globally: false` and define `disabled-regions` if you want
free-roaming/quest villagers elsewhere to keep normal AI.

## ⚠️ Known trade-offs

- Halted villagers **won't restock trades** (restock is brain-schedule
  driven) — existing trades keep working at current stock
- `onDisable` intentionally leaves villagers halted (Folia schedulers are
  unavailable during shutdown); use `/vpoihalt restore` to revert explicitly

---

*This plugin exists as a stopgap until Folia#292 is fixed upstream. Once POI
loading routes safely through the tick scheduler, you can restore your
villagers and remove it.*
